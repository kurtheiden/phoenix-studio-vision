# OS1 minimum 0.1 blind-intake operator checklist

**Decision covered:** whether one independent Studio Vision project may proceed from metadata intake toward a separately authorized Phoenix blind run. This is an operator aid, not intake authorization or a replacement for the [blind-validation protocol](OS1_BLIND_VALIDATION_PROTOCOL.md) and [reserve-intake protocol](OS1_RESERVE_INTAKE_PROTOCOL.md). One project alone cannot satisfy Gate 1 or Gate 5: the qualifying cohort needs at least two genuinely distinct logical projects, selected together with the full eligible fallback order frozen. The [minimum 0.1 rebaseline](OS1_TARGETED_RESPEC_RESUME_CHECKPOINT.md) does not require completing the full OS1 Topics 4–6 framework.

It refuses nonregular entries and Finder alias type. Its independent review remains **BLOCKED for authentic reserve intake**.
- [x] The [inspect acceptance runner](../tools/os1-metadata-helper/acceptance/README.md) requires externally frozen executable and MAP SHA-256 values, checks MAP executable identity, runs and records the actual `inspect` command and exit status, compares before/after mapped-source evidence, verifies complete neutral-ID and RECORD row accounting, and hashes/rechecks saved RECORD bytes. Focused synthetic tests and a small real-helper synthetic run passed. These checks do not authenticate the earlier `enumerate` execution or make a saved file's existence evidence of success.

## Before an authentic reserve path is supplied — operator evidence to establish

- [ ] Record repository/protocol checkpoint, roles, independent reviewer, private validation permission, owner provenance and Phoenix-exposure history, and affirmative **later** reference availability. Keep reference MIDI, exports, screenshots, notes, and associated media outside the intake workspace and analyst access; identify reveal authority. Do not open them now.
- [ ] Obtain an owner attestation for a **candidate-only root**, or use a separately prepared candidate-only directory/list without inspecting contents. Exclude known archives, disk images, packages, aliases, other noncandidate files, and content-revealing material before the helper sees the root. An ordinary regular archive can otherwise be marked `INSPECTED`; the helper does not identify file formats.
- [ ] Review and resolve every source, executable, MAP, RECORD, expectation, and acceptance-output path: local, private, non-cloud storage; separate source/output locations; private output parents; no symlinked ancestors, aliases, equivalent-path ambiguity, or unintended object resolution. Set restrictive permissions and avoid tracing, previews, verbose logs, and public path disclosure.
- [ ] Freeze the exact reviewed source/build/test identity, durable executable bytes and independent SHA-256, commands, private destinations, and failure handling **before** supplying the root. The temporary synthetic review binary is not an approved intake binary. Independently review this concrete operating boundary and obtain separate authorization for the authentic execution.

## After separate authorization — one bounded intake and decision

- [ ] Run and retain the exact `enumerate` command, actual exit status, output channel, saved MAP bytes and independent SHA-256. Verify successful completion, MAP count/neutral IDs, and source/root identity; freeze the MAP digest outside the MAP. The inspect runner does not establish this earlier command's success.
- [ ] With the independently frozen executable and MAP digests, run the acceptance procedure once. Preserve its actual command/exit, private acceptance output, RECORD and independent digest, complete MAP-to-RECORD row/ID accounting, inspected-row integrity or explicit refusal, and source evidence before/after. An `ERROR`, partial/missing row, nonzero exit, changed evidence, or ambiguous status is **not accepted**. `INSPECTED` means metadata/hash intake succeeded; it does **not** mean Phoenix can export MIDI.
- [ ] Use only permitted metadata and owner attestations to check development-history separation, provenance, family relationships, permission, blindness class, and later-reference availability. Exclude uncertainty. Freeze the complete private inventory, representatives, two-candidate selection and fallback order by the protocol's neutral rules; obtain independent selection review before any provenance lock. A single eligible project may proceed only as part of that approved cohort.

## Failure and next boundary

- [ ] On any failure or suspected mutation/leak, stop without silent retry. Preserve the original MAP, partial or altered RECORD, command/exit and bounded error, hashes, source before/after evidence, and incident/exposure account in private custody. Independent review decides any continuation; do not erase the failed run or substitute a candidate based on Phoenix behavior.
- [ ] After approved intake and selection, separately authorize the project's provenance lock and Phoenix-only observation. Record complete identification, diagnostics, every reported sequence/readiness/limitation, natural Ready-only export attempts and outputs, failures, and source integrity. Freeze and hash the complete Phoenix observation **before** the reference holder reveals anything. Only then reveal, compare, classify, and assess Gates 1/5. A conservative accurate Unsupported result can contribute; export is not required.
